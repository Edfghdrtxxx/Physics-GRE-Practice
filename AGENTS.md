- **Cross-tab persistence:** `store.js` `save()` is read-merge-write, not last-write-wins — `_rev` (write counter) + `_epoch` (wipe marker, computed via `_maxEpoch` over live+disk) inside the blob; `_mergeFromDisk()` unions append-only arrays and maxes counters; a `storage` listener adopts sibling writes and fires `PGRE.onStateAdopted` (single-assignment repaint hook, owned by `timer.js`). Deletions in user-editable maps (`notes`, `bookmarks`, `cardNotes`, `formulaSuspended`) must go through `store.tombstone(map, key)` / `untombstone` so a stale sibling heap can't resurrect them — tombstones carry ISO timestamps; a record newer than its tombstone is a re-add. Covered by `tools/test-store-persist.js`.
- **Fail-closed writes:** `store.canWrite()` is `!_persistFailed`. Entries that create a durable record — `gamify.recordAnswer` (returns `null` when refused; callers must not assume a new `attempts` row), `srs.gradeCard`, `srs.setLastAssess`, `examEngine.persistAnswer` / `submit` — check it first and return their neutral value with `PGRE.persistWarning(true)` instead of mutating RAM that will not reach disk; `view-exam.js` `doSubmit` stays in the room when `submittedAt` did not get set. Navigation-shaped state (exam cursor, flags, pause, plan checkbox, QOTD slot) is deliberately not guarded: it self-heals on the next successful save and is worth keeping through a transient outage. `_rev` counts successful writes only (rolled back when `setItem` throws) so a recovering tab still merges a sibling's newer disk. `save()` copies every 20th successful write (`_rev % 20 === 0`) to `pgre-state-v1-backup` (one slot; failure does not flip `_persistFailed`); `store.restoreBackup()` reuses `importJSON`. An unreadable blob is stashed under `pgre-state-v1-corrupt-<ts>` and remembered in `_corruptKey`; boot raises a sticky toast naming it. The sidebar footer `#origin-line` names the live origin because state is per origin.
